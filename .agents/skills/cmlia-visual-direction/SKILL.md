# 从用户任务定视觉方向

先说明用户来这页要做什么、首先要看哪里、接下来点哪里。用这一句话比较两个方案：一个更突出内容，一个更突出操作。选一个，指出另一个为什么不适合当前页面。不要为了展示过程而生成两套代码。

## 在本站如何取舍

- **公开首页：** 第一眼认出这是 API 服务，第二眼能找到控制台或接入地址。标题、说明、主按钮和可复制地址应形成阅读顺序。把高光留给可操作的卡片，不要把每块介绍文字做成按钮。
- **订阅和支付：** 用户比较的是价格、周期、额度。让金额基线和单位对齐，先看清差异，再看操作。交互光边可以表示焦点；没有业务字段就不能用它暗示“推荐套餐”。金额、密钥、账单和错误信息不得为装饰而延迟显示。
- **后台高频操作：** 让选中背景移动，让文字和点击区域留在原处。窄屏时保留名称、当前状态和操作，即使没有 hover 也能理解。
- **材质不是配色：** 先复用当前主题的正文、次要文字、描边、表面和强调色。玻璃面板的层次可用一条亮边和一层阴影交代；若文字只能靠增加阴影才读得清，先提高底色不透明度。

## 处理参考资料

对截图或视频记录“可见事实 → 适用原因 → 本站变体”。借用的是层级、节奏或反馈，不是样例品牌、价格、用户评价和业务数据。核对实际渲染分支：本站 `HomeView.vue` 的自定义首页和紧凑模式有优先级；控制台沿 `AppLayout → AppShell → ShellRail` 定位。不能用组件名推断它已上线。

**产出：** 给出主次层级、复用的设计变量、一个本次刻意不做的效果，以及用户能观察到的差异。例如：“套餐价格不变；仅键盘焦点或鼠标进入的卡片走一圈细光边，不持续争抢注意。”
