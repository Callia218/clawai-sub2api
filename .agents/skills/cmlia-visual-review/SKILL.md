# 用任务而非特效数量评审页面

选一条真实任务，例如“第一次访问首页，找到并复制接入地址”或“从两个套餐中比较周期和额度”。在当前版和改动版上做同一件事。先看静止页面，再看交互过程，避免把截图的漂亮误当成操作变容易。

用户说“要跟视频一样”时，先写明片段时间点、画幅、初始构图、触发动作、哪个元素沿什么方向运动，以及归位方式。每段用**同一次交互**在真实页面录屏，与原片并排、原速回看；加载可用本地限速样例，但要标清，且百分比必须来自实际收包。横向 Dock 不能用竖向侧栏替代，连续加载过程不能靠三个不同页面凑齐。将仍有差异的镜头单列；构建通过或列出了动效名称，不算视觉一致性验收。

| 观察 | 通过的迹象 | 需要返工的例子 |
|---|---|---|
| 层级和密度 | 首个动作、解释和辅助信息有清楚顺序；窄屏也保留关键信息 | 三个同样醒目的主按钮；价格单位被省略；手机出现整页横向滚动 |
| 材质和可读性 | 亮色、暗色的最浅表面上文字仍清楚；禁用模糊仍能辨认选中态 | 依靠发光才能读清标题；高光越过正文时对比度消失 |
| 过程和中断 | 快速切换后只留下最后一个选中项；关闭菜单回到触发器；手指不依赖悬停 | 用户点了 B，高光还停在 A；收起时仍能 Tab 进不可见链接 |
| 真实性 | 网络完成、失败和取消都有终点；百分数和按钮状态来自同一数据来源 | 为了完整播放动画，继续展示已经过期的加载态 |
| 减少动态效果 | 系统设置开启后，所有操作可立即完成，信息量与普通模式等价 | 直接隐藏包含唯一入口的动画容器 |

复核桌面鼠标与键盘、窄屏触摸以及减少动态效果。遇到需要登录、购买或接触客户数据的流程，用有权限的预览数据；没有就标记未实测，不能把源码检查描述为线上验证。不要凭一张截图宣称 60 FPS，只有实际测量才报性能数值。

报告按用户影响排序，条目用“页面和状态 → 可复现的观察 → 造成什么困难 → 最小修改”。例如：“手机折叠菜单关闭后焦点落到页面开头，需要重新遍历导航；返回原触发按钮即可。”交付时分别列出**实际看到的**、**由源码推断的**和**未覆盖的**。如果静态布局更清楚，保留静态就是合格结论。
